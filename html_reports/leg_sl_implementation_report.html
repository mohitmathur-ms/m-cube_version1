1. File map — where it lives

Leg-level stop-loss spans three backend layers. The schema declares the fields, the L2 engine computes and tests the level, and the L3 runner threads the per-leg ExitConfig into each portfolio slot.

LayerFileRole for stop-loss
Schema core/models.py ExitConfig dataclass — declares stop_loss_type, stop_loss_value, the trailing knobs, and the ATR knobs.
L2 engine core/managed_strategy.py ManagedExitStrategy — computes current_sl at entry fill (on_order_filled), updates trailing and tests the trigger every bar (_check_exits).
L3 runner core/backtest_runner.py Builds each slot's ManagedExitStrategy from the leg's ExitConfig and runs it inside the BacktestEngine.

3. Lifecycle & data flow

Two moments matter. (1) At entry fill — on_order_filled computes the initial current_sl price once from the entry price (managed_strategy.py:1592-1613). (2) Every bar — _check_exits first updates the trailing SL (if any), then tests whether the bar pierced current_sl (managed_strategy.py:1208-1248).

So percentage, points and ATR fix the level at entry and never move it; only trailing (and target-lock / move-to-cost, out of scope here) mutate current_sl on later bars. The trigger test itself is identical for all four types.

4. Percentage SL wired computed once

Percentage

The SL is placed a fixed percentage away from entry. Computed via the shared helper _compute_sl_price.

BUY  : SL = entry_price × (1 − value/100)
SELL : SL = entry_price × (1 + value/100)

Set at managed_strategy.py:1593-1594 · helper at managed_strategy.py:1641-1645

if self.config.stop_loss_type in ("percentage", "trailing"):
    self.current_sl = self._compute_sl_price(is_buy, self.config.stop_loss_value)

def _compute_sl_price(self, is_long: bool, pct: float) -> float:
    if is_long:
        return self._snap_to_tick(self.entry_price * (1 - pct / 100))
    else:
        return self._snap_to_tick(self.entry_price * (1 + pct / 100))

Worked example — step by step

The trade. You enter a LONG position at entry_price = 100.00 and configure stop_loss_type = "percentage" with stop_loss_value = 2 (you want to risk 2%). The instrument's tick size is 0.01.

  1. Pick the branch. stop_loss_type is "percentage", so on the entry-fill bar the engine calls _compute_sl_price(is_long=True, pct=2).
  2. Apply the long formula entry × (1 − pct/100) — substitute the numbers:
    SL = 100.00 × (1 − 2/100)
       = 100.00 × (1 − 0.02)
       = 100.00 × 0.98
       = 98.00
  3. Snap to the tick grid. 98.00 is already a multiple of 0.01, so it is unchanged: current_sl = 98.00. The stop sits 2.00 below entry — exactly the 2% of 100.00 you chose to risk.
  4. Arm the trigger. From now on, every bar tests one condition for a long: bar_low ≤ 98.00 (see §8 — the trigger looks at the bar low, not the close).
  5. A bar fires it. Three bars later a candle prints low = 97.96. Because 97.96 ≤ 98.00, sl_hit = True and _handle_exit("sl") closes the leg at the stop.
    Realised move ≈ 98.00 − 100.00 = −2.00 per unit (the 2% loss you sized for)

Same trade as a SHORT (SELL at 100.00). The formula flips to entry × (1 + pct/100): SL = 100.00 × 1.02 = 102.00, armed as bar_high ≥ 102.00. A later bar with high = 102.05 would trigger it for the same 2.00 (2%) loss.

5. Points SL wired computed once

Points

The SL is placed a fixed absolute price distance from entry (stop_loss_value is the distance in price units, not percent).

BUY  : SL = entry_price − value
SELL : SL = entry_price + value

managed_strategy.py:1595-1599

elif self.config.stop_loss_type == "points":
    if is_buy:
        self.current_sl = self._snap_to_tick(self.entry_price - self.config.stop_loss_value)
    else:
        self.current_sl = self._snap_to_tick(self.entry_price + self.config.stop_loss_value)

Worked example — step by step

The trade. You go LONG EURUSD at entry_price = 1.10000 with stop_loss_type = "points" and stop_loss_value = 0.00500. For EURUSD one pip is 0.00010, so 0.00500 is a fixed 50-pip stop distance. Tick = 0.00001.

  1. Pick the branch. stop_loss_type == "points", so the engine does no percentage maths — it subtracts the raw distance straight off the entry price.
  2. Apply the long formula entry − value:
    SL = 1.10000 − 0.00500 = 1.09500
  3. Snap to tick. 1.09500 already lands on the 0.00001 grid → current_sl = 1.09500.
  4. Arm the trigger. Each bar tests bar_low ≤ 1.09500.
  5. A bar fires it. A later candle dips to low = 1.09480. Since 1.09480 ≤ 1.09500 the stop fires.
    Realised move = 1.09500 − 1.10000 = −0.00500 = 50 pips — exactly the configured distance

Points vs. percentage — why it matters. Because the distance is absolute, the same 0.00500 stop is always 50 pips, whether price is at 1.10000 or 1.50000. A 2% percentage stop, by contrast, would be 0.02200 (220 pips) at 1.10 but 0.03000 (300 pips) at 1.50 — it scales with price. Use points when you think in pips/ticks rather than % of price.

Same trade as a SHORT (SELL at 1.10000). The sign flips: SL = 1.10000 + 0.00500 = 1.10500, armed as bar_high ≥ 1.10500.

6. ATR SL wired computed once

ATR (volatility-adaptive)

The SL distance scales with market volatility: distance = multiplier × ATR. ATR comes from Nautilus's built-in AverageTrueRange(period) indicator, registered in on_start so it warms up alongside the signal indicators — the leg won't enter until ATR has a valid value.

dist = ATR × sl_atr_multiplier
BUY  : SL = entry_price − dist
SELL : SL = entry_price + dist

Indicator registered at on_start (managed_strategy.py ~634-640) · level computed at managed_strategy.py:1600-1611

# on_start — register the ATR indicator so it warms up
if self.config.stop_loss_type == "atr" and self.config.sl_atr_period > 0:
    self._atr = AverageTrueRange(int(self.config.sl_atr_period))
    if not self._aggregating:
        self.register_indicator_for_bars(self.config.bar_type, self._atr)

# on_order_filled — size the SL from ATR at entry
elif self.config.stop_loss_type == "atr":
    atr_val = float(self._atr.value) if self._atr is not None and self._atr.initialized else 0.0
    dist = atr_val * float(self.config.sl_atr_multiplier)
    if dist > 0:
        if is_buy:
            self.current_sl = self._snap_to_tick(self.entry_price - dist)
        else:
            self.current_sl = self._snap_to_tick(self.entry_price + dist)
    else:
        self.current_sl = 0.0

Worked example — step by step

The trade. You go LONG at entry_price = 100.00 with stop_loss_type = "atr", sl_atr_period = 14, and sl_atr_multiplier = 1.5. Tick = 0.01.

  1. Warm-up (before any entry). At on_start the engine creates an AverageTrueRange(14) indicator and feeds every bar into it. ATR is a measure of how far price typically travels in one bar (the average "true range"). The leg is blocked from entering until this indicator is initialized, so a valid ATR reading always exists by the time a fill happens.
  2. Read ATR at the entry bar. Say the 14-bar ATR at the fill is atr_val = 0.80 — the instrument has been swinging about 0.80 per bar.
  3. Size the stop distance dist = atr_val × multiplier:
    dist = 0.80 × 1.5 = 1.20  (> 0, so a stop is armed)
  4. Place the stop one dist below entry (long), then snap to tick:
    SL = 100.00 − 1.20 = 98.80
  5. Arm & trigger. Each bar tests bar_low ≤ 98.80. A later bar with low = 98.75 fires it, for a 1.20 loss per unit.

Why ATR-size at all? Compare three volatility regimes. The multiplier stays fixed at 1.5, but the stop width automatically follows how choppy the market is at entry — wider in volatile conditions (so normal noise doesn't stop you out), tighter when calm:

RegimeATR(14) at entrydist = ATR × 1.5LONG SL = 100 − distWhat it means
Calm0.400.6099.40tight stop — small expected swings, so risk little
Normal0.801.2098.80the baseline case above
Volatile1.602.4097.60wide stop — avoids being shaken out by noise

Two things to remember. (1) ATR is read once, at the entry bar — if ATR later doubles the stop does not re-widen. (2) Edge case: if ATR somehow hasn't warmed up so dist works out to 0, the code sets current_sl = 0.0 and no stop is armed for that leg.

Same trade as a SHORT (SELL at 100.00, ATR 0.80). SL = 100.00 + 1.20 = 101.20, armed as bar_high ≥ 101.20.

Note: ATR is read once at the entry-fill bar to size the SL distance; the resulting level is then fixed for the life of the position (it does not re-size as ATR evolves).

7. Trailing SL wired per-bar

Trailing (ratcheting)

Starts as a percentage SL (initial level from stop_loss_value via _compute_sl_price). Every bar, the engine counts how many trailing_sl_step profit increments highest_profit has cleared, then builds a candidate stop a distance of steps × trailing_sl_offset percent below entry. A guard adopts the candidate only when it is tighter than the current stop (trail_sl > current_sl for a long), so the SL is only ever moved in the tightening direction, never loosened.

steps = int(highest_profit / trailing_sl_step)
trail_offset = steps × trailing_sl_offset
trail_sl = _compute_sl_price(is_long, trail_offset)
LONG : adopt trail_sl only if trail_sl > current_sl
SHORT : adopt trail_sl only if trail_sl < current_sl (or current_sl == 0)

Initial level at managed_strategy.py:1593-1594 · ratchet at managed_strategy.py:1208-1218

elif self.config.stop_loss_type == "trailing" and self.config.trailing_sl_step > 0:
    steps = int(self.highest_profit / self.config.trailing_sl_step)
    if steps > 0:
        trail_offset = steps * self.config.trailing_sl_offset
        trail_sl = self._compute_sl_price(is_long, trail_offset)
        if is_long and trail_sl > self.current_sl:
            self.current_sl = trail_sl
            self._was_trailed = True
        elif is_short and (self.current_sl == 0 or trail_sl < self.current_sl):
            self.current_sl = trail_sl
            self._was_trailed = True

highest_profit is the running max profit-% (the anchor for the ratchet); _was_trailed flags that trailing fired, which the exit-action filter later consults.

Worked example — LONG, walked bar by bar

The trade. LONG at entry_price = 100.00 with stop_loss_type = "trailing". The three knobs mean:

  • stop_loss_value = 1.0 (%) — the initial stop, placed exactly like a percentage SL.
  • trailing_sl_step = 0.5 (%) — how much profit must build up to earn one "step".
  • trailing_sl_offset = 0.2 (%) — the distance-below-entry used to build each step's candidate stop.
  • tick = 0.01.

Step 0 — the initial stop at fill (identical maths to the percentage type):

current_sl = 100.00 × (1 − 1.0/100) = 99.00

After that, every bar runs three little steps before the trigger check:

  1. update highest_profit (the best profit-% seen so far — it never goes down);
  2. count steps earned: steps = int(highest_profit / 0.5);
  3. build a candidate stop trail_sl = 100 × (1 − (steps × 0.2)/100) and adopt it only if it is higher than the current stop.

Here is how that plays out over four bars:

Barcloseprofit %highest_profitstepstrail_offsettrail_sl = 100×(1−off/100)guard: trail_sl > current_sl?current_sl
A100.300.300.30int(0.30/0.5)=0—— (steps not > 0)no change99.00
B100.600.600.60int(0.60/0.5)=11×0.2=0.2100×0.998 = 99.8099.80 > 99.00 → yes99.80
C101.201.201.20int(1.20/0.5)=22×0.2=0.4100×0.996 = 99.6099.60 > 99.80 → no99.80 (held)

The same four bars, in plain words:

  1. Bar A — close 100.30 (+0.30%). Only 0.30% profit so far. int(0.30/0.5) = 0 steps, so the trailing block does nothing this bar. The stop stays at its initial 99.00.
  2. Bar B — close 100.60 (+0.60%). Profit now clears one step: int(0.60/0.5) = 1. Candidate = 100 × (1 − 0.2/100) = 99.80. Since 99.80 > 99.00, the guard adopts it and the stop jumps up to 99.80 — your risk has shrunk from 1.00 to just 0.20 below entry.
  3. Bar C — close 101.20 (+1.20%). Profit is now worth two steps. Candidate = 100 × (1 − 0.4/100) = 99.60. But 99.60 > 99.80 is false, so the guard rejects it and the stop holds at 99.80. (This is the key quirk — more profit produces a lower candidate here; see the note below.)
  4. Bar D — low 99.78. The bar's low pierces the stop: 99.78 ≤ 99.80 → SL hit. The leg exits right around 99.80 — a near-scratch — instead of giving back the full 1.00 it had risked at entry. That is the protection the trailing stop bought you.

SELL legs mirror this: the candidate is 100×(1+off/100) (above entry) and the guard adopts it only when trail_sl < current_sl, with the trigger on bar_high ≥ current_sl.

Read the guard carefully. The candidate stop is a fixed distance below entry of steps × offset %. The first profit step that clears the threshold yields the highest (tightest) candidate and is adopted; as highest_profit climbs and steps grows, later candidates sit lower and are rejected by trail_sl > current_sl. So this leg-trailing branch tightens to its first-qualifying-step level and then holds — it does not keep tracking price upward. (The separate "Trail After Move SL" branch at managed_strategy.py:1192-1206 uses −steps×offset, placing the stop on the profit side of entry, and does ratchet up with profit.)

8. Common mechanics

These apply to every SL type regardless of how the level was computed.

Tick snapping

All computed SL prices are rounded to the instrument's tick grid via _snap_to_tick so triggers match cleanly at fill time (managed_strategy.py:1647-1663).

tick = float(self.instrument.price_increment)
return round(price / tick) * tick   # falls back to raw value if instrument unbound

Intrabar trigger test

The SL fires when the bar pierces the level — a LONG leg on the bar low, a SHORT leg on the bar high (managed_strategy.py:1220-1227).

sl_hit = False
if self.current_sl > 0:
    if is_long and bar_low <= self.current_sl:
        sl_hit = True
    elif is_short and bar_high >= self.current_sl:
        sl_hit = True

SL-wait gate

An optional confirmation delay can suppress the exit until the level has held for sl_wait_sec wall-clock seconds (preferred) or sl_wait_bars bars; once confirmed, _handle_exit("sl", ...) closes the leg (managed_strategy.py:1229-1248).

Profit tracking

Each bar updates the current profit-% from entry and the running highest_profit — the latter is what the trailing ratchet reads.
