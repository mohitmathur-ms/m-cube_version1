Google Drive

What it takes to load CSV market data from a Google Drive folder instead of a local path.

1. How it fits the current flow

The scanner (scan_csv_folder) only understands local files. Google Drive is an object store keyed by opaque file IDs, not real folder paths, so again the model is sync-then-scan: download the Drive folder's CSVs into a local staging directory, rebuilding the same sub-folder structure, then scan it.

Drive folder→ download by file ID→ rebuild local tree→ scan_csv_folder()
Drive has no native folder paths — we must walk the tree via the API (list children of a folder ID) and recreate the directory names ourselves so the FX/crypto/commodity layout scanners still recognise it.

3. Process (step by step)

  1. Authenticate with the service-account key and build the Drive client: 
    from googleapiclient.discovery import build
from google.oauth2 import service_account
creds = service_account.Credentials.from_service_account_file(
    key_file, scopes=["https://www.googleapis.com/auth/drive.readonly"])
drive = build("drive", "v3", credentials=creds)
  2. Share the folder with the service account's email (one-time, in Drive UI).
  3. List children of the folder ID, recursing into sub-folders: 
    q = f"'{folder_id}' in parents and trashed=false"
files = drive.files().list(q=q,
        fields="files(id,name,mimeType)").execute()["files"]
  4. Download each CSV by ID, writing to the rebuilt local path: 
    data = drive.files().get_media(fileId=fid).execute()
(staging/relpath).write_bytes(data)
  5. Scan + load the staging folder exactly as a local path.

4. Where it touches our code

  • UI: "Source: Google Drive" choice; input = folder ID (or share link we parse).
  • Server: a downloader that mirrors the Drive tree into a per-user staging folder, then calls scan_csv_folder on it.
  • Scanners: no change.

5. Gotchas

  • Drive API has per-user rate limits / quotas — throttle and page large folders.
  • Recursion is required: Drive returns only direct children, so the daily-layout trees (<PAIR>/YYYY/MM/DD) must be walked level by level.
  • Watch for duplicate file names in one folder (Drive allows them); de-dupe by ID.
  • OAuth (vs service account) needs an interactive consent step — awkward for a server; prefer the service account.
