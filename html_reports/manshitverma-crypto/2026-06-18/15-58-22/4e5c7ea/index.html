Plain English

What this change does, for a non-technical reader.

Previously, when a trade hit its stop-loss or take-profit, the platform had only a limited set of actions it could take (close the position, reverse direction, or hold). This push finishes wiring four additional per-leg behaviours that were previously stubbed or missing: 'Re-Execute' (immediately re-enter the same trade on the very next bar), 'ReEntry' (place a resting limit order and wait for price to return to the original entry), 'Execute' (permanently pivot to a sibling strategy), and 'SqOff' (close and stay idle for the rest of the trading day).

For users running multiple portfolios together in a single session, the platform now enforces group-level loss and profit caps in real time. Portfolios that share a tag (e.g. 'FX_GROUP') can be given a combined loss limit in configuration; when the whole group hits that limit mid-bar, every portfolio in the group is squared off live, on that same bar.

A long-standing bug in the step-based trailing stop-loss was also fixed. The stop was being placed on the wrong side of the entry price, so instead of locking in profit it froze immediately at the entry offset and never ratcheted. The fix reverses the sign so the stop correctly moves toward the profit side as the trade gains.

The orderbook report was improved for multi-portfolio runs: each row now shows which portfolio and strategy it belongs to, the sort order was changed from entry time to exit time (more natural for reviewing closed trades), and the 'PORTFOLIO NAME' column is now correctly populated with the real portfolio name rather than the strategy identifier.

Technical / Engineering

Implementation detail and impact, for engineers.

**`core/managed_strategy.py` — leg-level exit actions (the bulk of the change)**

Five new/corrected state-machine paths are wired inside `_handle_exit_action`: - `close`: sets `_leg_sqoff_blocked_date` to the current UTC date; `_check_entries` skips re-entry until the calendar date rolls over. - `execute`: sets `_leg_perm_closed = True`; `_check_entries` returns immediately for the rest of the run. - `re_execute`: arms `_reexec_limit_px`, `_reexec_market_mode = True`, and `_reexec_arm_ts_ns = current_bar_ts` so `_try_reexec_reentry` fires a MARKET re-entry on the strictly-next base bar (not same-bar, which would collide with 5-min aggregation boundaries). - `re_entry`: arms `_reexec_limit_px = trigger_price`, `_reexec_market_mode = False` — the existing entry-price LIMIT machinery (`_submit_reexec_limit`) handles the resting order; same next-bar deferral via `_reexec_arm_ts_ns`. - `reverse`: now tags `_pending_entry_reason` with 'Reverse on SL/TP — flipped from long/short' for the orderbook.

A shared `_reexec_reason_tag: str` field replaces the hardcoded order tag so limit and market re-entries emit descriptive reasons (leg Re-Execute, leg ReEntry, portfolio ReExecute) in the orderbook's ENTRY DETAILED REASON column.

Trailing SL sign fix (`_update_trailing_sl`, line ~1925): `trail_sl = self._compute_sl_price(is_long, trail_offset)` → `self._compute_sl_price(is_long, -trail_offset)`. A positive offset passed to `_compute_sl_price` placed the SL below entry for a long (loss side), which the tighten-only guard then froze at. Negating the offset places it above entry (profit side) and the ratchet works as designed.

**`core/backtest_runner/session/__init__.py` — tag/user tier live enforcement**

After building `specs`, `run_session_backtest` now constructs a `tag_specs` list: it groups portfolios by `portfolio_tag`, reads each tag's `max_loss/max_profit/trail_*` from `core/tags`, and appends a spec. A second block does the same for the user's session-wide cap from `core/users`, giving it the synthetic tag `USER::<user_id>` scoped to all portfolios. These specs are passed as `session_tag_specs` to `_run_portfolio_unified`. `_live_caps = bool(tag_specs)` is then forwarded to `_merge_portfolio_results(live_session_caps=...)` to skip the legacy post-run user/tag PnL aggregator and prevent double-clipping.

**`core/backtest_runner/unified/__init__.py` — tag monitor construction**

Inside the session path of `_run_portfolio_unified`, for each tag spec a `PortfolioMonitorStrategy` (`_PMS`) is built with `cross_pf_targets=tuple(sorted(_pids))`, `enforce=True`, `sl_day_scoped=False` (absolute, not daily), and trailing params wired through. Tag monitors are registered FIRST (before legs), matching the enforcing-first ordering used by per-portfolio monitors. A new module-level `_SESSION_ENGINE_REPORTS` dict captures the shared engine's account report for the combined session tearsheet.

**`core/portfolio_monitor.py` — trailing ratchet and multi-target fire**

New `PortfolioMonitorConfig` fields: `sl_day_scoped`, `cross_pf_targets`, and the full trailing ratchet knobs (`pf_sl_trail_*`, `pf_tgt_trail_*`). `_eval_trailing()` is a live port of the post-run `portfolio_clip` steps 1-3: it ratchets `_sl_current` as profit grows, activates the trailing target floor at `when_reach`, and fires `_fire('sqoff', ...)` one-shot on breach. The progress bus `.append()` change (replacing `[:] = [...]`) ensures session-mode streaming emits every day in order rather than only the latest.

**`core/report_generator.py`**

`_build_orderbook` gains a `portfolio_name` parameter; each row's EXIT/ENTRY DETAILED REASON now appends `— Portfolio: <name> · Strategy: <name>` (stripping the 8-hex disambiguation suffix). Sort key changed from `(entry_ts, batch_rank, ...)` to `(exit_ts, batch_rank, ...)`. `_build_summary` now keys per-leg stats on STRATEGY (not PORTFOLIO NAME) to preserve correct daily breakdown after the column was repurposed.

Worked Example

A concrete illustration of the most significant change.

**Re-Execute leg action — before vs after**

Before this push, when `on_sl_action = 're_execute'` fired in `_handle_exit_action`, the code incremented `re_execution_count`, optionally set a `_reentry_blocked_until_ns` delay, then left the strategy flat waiting for the *next signal* (the EMA cross, RSI, etc.) to trigger a fresh entry — meaning re-entry could take hours or never come.

After: ```python # _handle_exit_action — re_execute branch (managed_strategy.py ~2236) if saved_entry_price > 0: self._reexec_limit_px = float(saved_entry_price) # flags "re-entry pending" self._reexec_limit_is_long = was_long # same side as original trade self._reexec_market_mode = True # MARKET, not limit self._reexec_reason_tag = "Re-Execute (market) — re-opened immediately after leg Stop Loss hit" self._reexec_arm_ts_ns = self._current_bar_ts_ns # defer to NEXT base bar ``` On the very next bar, `_try_reexec_reentry` sees `_reexec_limit_px > 0` and `current_bar_ts > arm_ts`, and calls `_submit_reexec_market()` — a MARKET order on the original side, no signal required. The leg re-enters within one bar of the SL hit, up to `max_re_executions` times.

Risks & Follow-ups

  • Trailing-SL sign fix is a silent behaviour change for any existing portfolio with trailing_sl_step > 0 configured — previously the SL froze at entry±offset; now it ratchets. Users should re-validate trailing-stop portfolios against prior results.
  • _leg_sqoff_blocked_date uses UTC day boundary regardless of the strategy's configured timezone; an exit at 23:55 UTC blocks the leg for only 5 minutes of wall time but counts as 'rest of day' — could surprise users in Asia/Pacific sessions.
  • Tag/user enforcement relies on core.tags and core.users exposing get_tag_trailing_sl / get_user_trailing_sl — if those functions don't exist yet, the ImportError is silently swallowed (BLE001 noqa), leaving the caps un-enforced with no visible error.
  • live_session_caps = bool(tag_specs) means a session with no tagged portfolios and no user caps runs the legacy post-run clip path — parity between the two paths should be verified with verify_grouping_parity.py equivalents for session mode.
  • Orderbook sort-order change (exit time instead of entry time) may shift row ordering in existing tearsheet snapshots or regression baselines that compare the HTML report textually.
  • The diff is truncated; the full content of the new PFSL_*/PFTGT_*/PFCL_*/PFCP_* portfolio JSON files (≈13 000 lines) was not reviewable — their schema correctness is assumed but unverified from the diff alone.
  • multiportfolio_realistic_test.py / multiportfolio_tier_caps_test.py / multiportfolio_user_tag_test.py are new test scripts but appear to be standalone scripts rather than pytest cases — they should be integrated into the test suite for CI coverage.
