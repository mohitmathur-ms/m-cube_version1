Synology NAS

What it takes to load CSV market data from a Synology NAS instead of a local path.

1. How it fits the current flow

A Synology NAS is the friendliest of the three options, because it can be exposed as a real filesystem path. If we mount the NAS share on the server, the existing scan_csv_folder(folder) works as-is — the mount point simply looks like any other folder.

Synology share→ mount as drive / UNC path→ scan_csv_folder()→ catalog

Two access styles: (A) network mount (SMB/NFS) — zero code change; or (B) Synology FileStation API — download-then-scan, like the cloud options, when mounting isn't allowed.

3. Process — Option A: mount (recommended)

  1. Enable SMB on the NAS (DSM → Control Panel → File Services → SMB).
  2. Mount the share on the Windows server: 
    net use Z: \\192.168.1.50\market_data /user:mcube ******
    (or map a persistent drive / use the UNC path directly).
  3. Point the app at the mounted path — nothing else changes: 
    entries = scan_csv_folder(r"Z:\fx")        # or \\192.168.1.50\market_data\fx
  4. Load normally into the catalog.
This is effectively the existing "system path" option — a mounted NAS share is a system path. Minimal work, maximum reuse.

4. Process — Option B: FileStation API (no mount)

  1. Authenticate to get a session ID: 
    GET /webapi/auth.cgi?api=SYNO.API.Auth&method=login
    &account=mcube&passwd=***&session=FileStation&format=sid
  2. List the share recursively (SYNO.FileStation.List).
  3. Download each CSV (SYNO.FileStation.Download) into a local staging tree.
  4. Scan + load the staging folder via scan_csv_folder.

5. Where it touches our code

  • Option A: no code change — UI just accepts the mounted/UNC path.
  • Option B: a FileStation downloader feeding a staging folder, like the cloud options.
  • Scanners: no change in either case.

6. Gotchas

  • SMB credentials must survive server reboots — use a stored credential or persistent mount.
  • UNC paths can be slow over WAN; for remote NAS prefer caching/staging locally.
  • FileStation sessions expire — re-login and handle error.code responses.
  • Confirm DSM user is read-only on the share to avoid accidental writes.
