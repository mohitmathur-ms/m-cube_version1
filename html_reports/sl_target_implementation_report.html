10. Remaining work — the 9 PARTIAL items

All remaining gaps are architectural approximations, not missing features. They cluster into two efforts:

A. Single-format engine (Format B / OHLCV only)

Affects 4.1 SL Trigger and 4.1 Target Trigger. The spec defines three data formats — A (Bid/Ask), B (OHLCV), C (LTP) — each with its own trigger and fill formulas. The engine consumes a single bar series and triggers on bar high/low (Format B). Adding Formats A and C requires the data layer to expose bid/ask-split and LTP bar shapes and the strategy to branch on them — a change spanning csv_loader, the catalog, ManagedExitStrategy and the runner. Best done as a dedicated effort with its own parity verification.

B. Post-hoc portfolio clip vs real-time replay

Affects Portfolio ReExecute, ReExecute at Entry Price, Portfolio Target Actions, the cross-portfolio actions, and relatedly End Time and no_wait_trade_reexec / no_reentry_after_end. The portfolio layer applies limits by walking the merged equity curve after the backtest finishes and dropping post-clip trades. A genuine ReExecute would re-enter new trades from the clip point — impossible without converting the post-hoc clip into a real-time portfolio-aware engine (or a clip-then-replay loop). This is the larger of the two efforts and changes the runner's execution model.

Recommendation. Items A and B are real architecture changes that each warrant their own branch, parity harness (scripts/verify_grouping_parity.py-style) and review cycle. Everything else in the spec — every leg-, portfolio- and user-level SL/Target feature — is now implemented and unit-tested.
