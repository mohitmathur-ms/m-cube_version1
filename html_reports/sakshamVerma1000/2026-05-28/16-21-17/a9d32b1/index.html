Plain English

What this change does, for a non-technical reader.

The team built an automated quality-check system to verify that the platform's stop-loss calculations are mathematically correct. It runs real backtests with known inputs and checks that every stop-loss price the engine actually places matches the formula it is supposed to use. The results, now saved in the repository, show that fixed stop-losses (percentage and points-based) are correct, but ATR-based stop-losses have a small but consistent one-pip rounding error that shows up more often with larger multipliers.

A research report was produced comparing two ways the platform can enter trades: sending a limit order directly to the exchange, versus using a strategy callback that fires a market order when conditions are met. The comparison focuses on slippage — how much worse the real fill price is versus the intended price — and the findings are saved as HTML tearsheets.

A large library of ready-to-run test portfolios was added to make it easier to reproduce and test specific engine behaviors. There are 65+ portfolio files organised into four groups: cross-portfolio edge cases, leg-level exit logic, portfolio-level logic, and data-format variations. Each group has its own documented README.

A bug was fixed in the Coinbase venue configuration: the venue name was listed as 'COINBASE' when it should be 'COINBASE_MS' to match the instrument IDs used in backtests. Without this fix, any Coinbase backtest would silently fail. Session trading hours were also added to the Coinbase and Nifty Futures venue configs.

Technical / Engineering

Implementation detail and impact, for engineers.

The most substantial new artefact is `verify_leg_sl_formulas.py` (382 lines) and its companion `tests/smoke_tests/verify_leg_sl_formulas_report.py` (278 lines). The harness drives nine fixture portfolios (NONE / PCT-05 / PCT-10 / PTS-0005 / PTS-0010 / ATR-10/-15/-20/-30, all in `5. Logics/sl_formula_tests/portfolios/`) through the live Flask `/api/portfolio/run` endpoint, extracts the orderbook, and for each SL exit cross-checks `engine_sl` against the analytically-expected `snap(entry ± multiplier × ATR)`. Results are persisted to `5. Logics/sl_formula_tests/sl_formula_results.json` (1 146 lines). All nine run-results are present in this commit, meaning the harness was both written and executed in this push.

The results expose a systematic ±1-tick (1e-05) rounding discrepancy in ATR-mode SL placement inside `core/managed_strategy.py`. The error direction alternates (sometimes engine_sl is one tick too high, sometimes one tick too low), pointing to a floating-point precision issue in the tick-snapping step when `entry ∓ k × ATR` sits very close to a tick boundary. Failure rates: ATR-10 1/41, ATR-15 9/15, ATR-20 4/15, ATR-30 1/2. PCT-10 also fails with the same 1-tick pattern on 2/3 trades.

`core/managed_strategy.py` is modified (24 lines changed) but the diff is truncated; the exact change is not visible. It is likely related to the ATR/percentage SL rounding investigation or to session-time integration (see venue config changes below).

`html_reports/LIMIT_ORDER_REPORT.html` (1 054 lines) and `html_reports/order_emulator_report.html` (723 lines) are static tearsheets comparing NautilusTrader's native LIMIT-order path with the current m-cube pattern of submitting a MARKET order from `on_order_filled`/`on_bar` strategy callbacks, from a slippage standpoint.

`portfolios/testing/` adds 65+ JSON portfolio files and a 174-line README. Files follow four namespaces: TC-xx (same-bar precedence, trail-step breach, cross-portfolio race), TL-xx (SL pct/points/ATR, wait bars, move-cost, re-execute/reverse actions), TP-xx (combined portfolio loss/profit, underlying SL/target, trailing, move-cost at portfolio level, cross-portfolio halt), TX-xx (data formats, MIS cutoff, NRML carry, timeframes, tick-snap).

`adapter_admin/adapters_config/coinbase_ms.json`: `venue` field corrected from `"COINBASE"` to `"COINBASE_MS"` — the venue string must match the InstrumentId prefix or the engine cannot resolve the instrument. Also adds `session_start_time: "00:00:00"` / `session_end_time: "23:59:00"`. `nifty_futures_ms.json` gains the same session fields (`09:15:00` / `19:14:00`).

`scripts/aggregate_catalog.py` is modified (42 lines; diff truncated). `README_APP.md` simultaneously removes two references to RSI/ATR/EMA/VWAP feature sidecars from the catalog and aggregation pipeline descriptions, suggesting the sidecar-compute step was stripped from the aggregator in this push, though the exact code change is not visible.

`core/backtest_runner/simple_backtest_runner_readme.md` (389 lines) is a new human-readable documentation file dropped inside the `core/backtest_runner/` package directory, describing each sub-module (profiling, bar_types, bar_filters, path_b, rbo, slot_execution, portfolio_clip, etc.). Its presence implies this directory is already a package, consistent with the earlier modular refactor of `backtest_runner.py`.

Worked Example

A concrete illustration of the most significant change.

The ATR-15 test (1.5× multiplier) illustrates the confirmed rounding bug:

entry = 1.053992 (SHORT, EURUSD 1-min MID) ATR = 0.00019 formula: SL = snap(1.053992 + 1.5 × 0.00019) = snap(1.054277) = 1.05428 engine_sl returned by backtest = 1.05427 ← 1 tick (1e-05) low

The same off-by-one pattern repeats for 9 of 15 SL exits in ATR-15 and is confirmed across ATR-10, ATR-20, and ATR-30. By contrast, the PTS-0005 (fixed-points) test shows:

entry = 1.053992 (SHORT) formula: SL = snap(1.053992 + 0.0005) = 1.05449 engine_sl = 1.05449 ← exact match

Risks & Follow-ups

  • ATR SL rounding bug is confirmed but not yet fixed — systematic ±1-tick error at multipliers ≥1.5× needs a fix in managed_strategy.py tick-snapping (likely round vs. floor/ceil choice after float multiplication)
  • PCT-10 also fails with the same 1-tick pattern (2/3 trades); shares likely root cause with ATR failures
  • core/managed_strategy.py and scripts/aggregate_catalog.py diffs are truncated — actual changes are unreviewed; risk is unknown
  • coinbase_ms.json venue name fix may invalidate any catalog data or saved results keyed under the old 'COINBASE' venue string
  • Feature sidecar removal (RSI/ATR/EMA/VWAP) from the aggregator is implied by README_APP.md edits but the aggregate_catalog.py diff is not visible — downstream consumers of sidecar data (if any) could silently break
  • core/backtest_runner/simple_backtest_runner_readme.md is a documentation-only file inside a package directory; its description of sub-folders (profiling/, bar_types/, rbo/, etc.) should be verified against the actual directory contents to ensure it is not out of date
  • 65+ new test portfolios reference EURUSD.FOREX_MS / NIFTY data — they will error at runtime on any machine whose catalog lacks that data; no CI guard enforces this
