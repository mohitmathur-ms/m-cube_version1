Plain English

What this change does, for a non-technical reader.

The largest and most complex file in the codebase — the engine that actually runs backtests, at over 6,200 lines — was broken up into 16 smaller, focused files. Each file now handles one specific concern: bar filtering, portfolio stop-loss logic, results extraction, VWAP fills, and so on. The product behaves identically; only the internal organization changed.

This kind of restructuring makes the platform easier to maintain. When a developer needs to fix a bug in, say, the weekday bar filter, they open a 173-line file instead of hunting through 6,200 lines. It also makes it safer to work on two unrelated features in parallel without merge conflicts.

The team also added a new AI assistant called 'ntm3' specifically for NautilusTrader questions. When writing or debugging code that relies on the underlying NautilusTrader library, developers can ask ntm3 to look up the exact API behavior from official documentation PDFs. This reduces the risk of implementing features based on guessed or stale API knowledge.

Technical / Engineering

Implementation detail and impact, for engineers.

The monolith `core/backtest_runner.py` (6,215 lines, deleted) was replaced with the package `core/backtest_runner/` whose `__init__.py` (354 lines) re-exports every public symbol, so all existing callers (`server.py`, tests) are unaffected at the import level.

The 16 child modules, each as `<name>/__init__.py`, correspond to logical responsibility boundaries identified via a committed AST-analysis script (`_split_analyze.py`): `profiling` (_phase context manager, memoized MRO checks), `bar_types` (_aggregate_target_for_slot, _group_slots, _pair_bid_ask_bar_type), `bar_filters` (weekday/time-of-day/cutoff-ns filters), `path_b` (_build_run_config, _chunk_data_configs_for_path_b), `rbo` (_RBOSettings dataclass, _resolve_rbo, winter-time helpers), `other_settings` (_OtherSettings, _resolve_other_settings), `portfolio_exit_config` (_PfStoplossSettings, _PfTargetSettings, _MoveSLConfig, all resolve_* functions), `cross_portfolio` (event bus, action normalizers, re-execute family helpers), `portfolio_clip` (_apply_portfolio_clip, _AggCoordination, underlying/user SL-TP clip chain), `equity_curves`, `data_cache` (_cached_catalog_bars), `single_backtest` (run_backtest, run_backtest_node), `slot_execution` (_run_single_slot, _run_slot_group and their Node variants — the largest submodule at 1,614 lines), `results` (position PnL extraction, base-currency conversion), `portfolio_results` (_merge_portfolio_results, per-strategy breakdown), `exit_fill` (VWAP fill logic, directional close fill), and `orchestration` (run_portfolio_backtest — the outermost entry point).

`_split_analyze.py` uses Python's `ast` module to parse the original file, assign each top-level definition to a target module via a hardcoded MAP dict, build a cross-module dependency graph by walking AST `Name` loads, and run DFS to verify the split is acyclic. The script reports unmapped definitions and MAPPED-but-not-found names, serving as a correctness check for the migration.

The `ntm3` sub-agent is defined in `.claude/agents/ntm3.md` with frontmatter `tools: Read, Grep, Glob` (read-only; no Edit or Bash). Its knowledge base is `.claude/agents/ntm3_docs/` — 30 NautilusTrader concept PDFs indexed by `INDEX.md`. The agent reads INDEX.md first to pick the right PDF(s), then pages through them (≤20 pages/call). The PDF files themselves are not committed; only the template index is present.

Worked Example

A concrete illustration of the most significant change.

Before: `from core.backtest_runner import run_portfolio_backtest` resolved to line ~5900 of a single 6,215-line file. Fixing a weekday-filter bug required opening that file and searching for `_filter_bars_by_weekday`.

After: the same import still works (re-exported from `core/backtest_runner/__init__.py`), but the weekday filter implementation is now in the standalone 173-line file `core/backtest_runner/bar_filters/__init__.py`. The portfolio clip logic that fires when a portfolio stop-loss is hit lives in `portfolio_clip/__init__.py` (796 lines). The main `run_portfolio_backtest` orchestrator lives in `orchestration/__init__.py` (519 lines). Each can be edited, reviewed, or tested in isolation.

Risks & Follow-ups

  • Diff is truncated — the full content of most submodule __init__.py files is not visible; each should be reviewed for completeness and correctness before the branch is merged.
  • All 16 submodules use __init__.py as their sole file — if any submodule grows large the same readability problem may recur; consider whether this is the right long-term structure.
  • _split_analyze.py is committed to the repo root as a one-time tooling artifact; it should be moved to scripts/ or removed to avoid cluttering the top-level directory.
  • The ntm3 PDF corpus is empty — only the template INDEX.md is present; ntm3 will fall back to reading package source under venv/ until the 30 PDFs are added, potentially giving less reliable answers.
  • The cycle-detection output from _split_analyze.py is not captured in the diff — confirm the script reports 'CYCLES: NONE' on the current split before relying on the modular structure.
  • server.py and all tests import from core.backtest_runner — the re-export contract in __init__.py must be kept in sync whenever new public functions are added to any submodule.
  • settings.json now contains several sed and python -c one-liners that were whitelisted during the split session; audit whether all of these should be permanent permissions or should be removed post-session.
