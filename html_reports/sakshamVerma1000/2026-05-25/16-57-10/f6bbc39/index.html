Plain English

What this change does, for a non-technical reader.

The team deleted a large, outdated Python file that had already been replaced by a newer, better-organised version in a prior commit. The old file was still sitting in the repository doing nothing; removing it eliminates confusion about which copy is authoritative.

Two new educational HTML pages were added to the html_reports folder. These are not backtest results — they are permanent reference documents that explain how the platform handles trade execution: one covers the tradeoff between market and limit orders, the other explains exactly how stop-loss and take-profit orders interact with market-order execution in the backtesting engine. They serve as always-available, self-contained reading material for anyone trying to understand system behavior.

A detailed README was added inside the .github folder. It explains, in plain language, what the two automated CI workflows do every time code is pushed: one checks that the code is healthy (lint and tests), the other generates an AI-written HTML summary of what changed. New contributors can now understand the automation without reading workflow YAML.

Several old, auto-generated HTML report files that had accumulated in html_reports were also deleted as housekeeping. These were stale outputs from previous GitHub Actions runs and carried no lasting value.

Technical / Engineering

Implementation detail and impact, for engineers.

The dominant structural change is the deletion of `core/csv_loader.py` (752 lines). That monolith had already been decomposed into the `core/csv_loader/` package (sub-modules: `fx_daily_scanner/`, `commodity_daily_scanner/`, `index_daily_scanner/`, `crypto_nested_scanner/`, `fx_consolidated_scanner/`, `folder_scanner/`, `csv_reader/`, `side_concat/`, `mid_merge/`, `timestamp_parser/`, `scan_cache/`, `constants/`). This push removes the now-dead source file, completing the migration. Public symbols (`scan_csv_folder`, `load_csv`, `concat_side`, `_merge_ask_bid_to_mid`, `load_pair_mid`, `clear_fx_scan_cache`) continue to be re-exported from the package `__init__.py`, so no call-site changes are needed.

`core/csv_loader/README.md` gains 104 lines: a structured table listing every hardcoded literal across all submodules — thread-pool ceiling (`_CONCAT_SIDE_MAX_WORKERS = 16`), volume cap (`QUANTITY_MAX = 16_000_000_000.0`), all five filename regexes, scan-cache TTL (`600.0 s` per layout type), the scanner fallback order (consolidated → flat → FX-daily → commodity → index → crypto), MID formula (`(ask + bid) * 0.5`), duplicate policy (`keep="first"`), etc. — each tagged with an override-path label (None / kwarg / data_format JSON / UI folder field).

`.github/README.md` (265 lines, new) documents `python-app.yml` (flake8 pass-1/pass-2 + pytest) and `push-report.yml` (collect_meta → generate_report → commit-back with retry-rebase loop), the AI-backend fallback chain (`CLAUDE_CODE_OAUTH_TOKEN` → `ANTHROPIC_API_KEY` → metadata-only banner), loop-prevention via `paths-ignore: html_reports/**` + `[skip ci]`, and all marketplace actions, runtimes, and secrets involved.

`html_reports/mkt_limit_order_tradeoff.html` (460 lines) and `html_reports/sl_tp_with_market_orders_explained.html` (434 lines) are self-contained, dark-themed static HTML pages committed as permanent reference documentation — not generated tearsheets. They explain MARKET vs. LIMIT execution semantics and how SL/TP orders interact with NautilusTrader's simulated fill model. `html_reports/report.md` (300 lines) is a Markdown companion.

Eight stale auto-generated report pairs (`index.html` + `index.json`) deleted from `html_reports/manshitverma-crypto/`, `html_reports/sakshamVerma1000/`, and the `2026-05-23/` dated subdirectories.

`.claude/settings.json` adds seven PowerShell command allowlist entries (`Select-Object -ExpandProperty Name`, `Get-ChildItem` filter variants, `Format-List`) reflecting interactive file-system exploration performed during the session.

`portfolios/_default/FX_9_Slot_2024.json` has 8 lines changed; the unified diff is truncated so the specific field edits are not visible.

`core/models/serialization/__init__.py`: one blank line added inside the module docstring — cosmetic only.
