Plain English

What this change does, for a non-technical reader.

The team is exploring whether replacing the platform's current trade-exit mechanism with a more realistic "bracket order" approach would make backtests more accurate. Right now, when a stop-loss or take-profit level is breached, the system detects it only after a full price bar closes and then sends a simple market order — meaning the actual fill often happens at the bar's closing price rather than the intended level. Across a sample of test cases, this gap averages about 7 pips of slippage.

The new idea places all three orders — entry, stop-loss, and take-profit — together in a single submission at the moment the trade opens. The exchange simulator then walks through each bar's price path from open to high to low to close, triggering the stop or target at the exact level the moment price touches it. Across the same sample cases, average slippage drops to about 1.7 pips. The approach is limited to simple fixed stop-loss plus fixed take-profit setups; anything requiring ongoing decisions (a trailing stop, profit-locking, waiting several bars to confirm, or re-entering after a loss) still uses the original Python-based logic.

This commit does not ship the feature to production. It adds all the validation tools needed to evaluate the idea safely: a three-phase simulation suite, a standalone end-to-end test, two automated code reviews, and a formatted HTML report documenting the findings. The underlying engine change in `core/managed_strategy.py` is referenced throughout these artifacts but is NOT part of this commit — it exists as a separate body of uncommitted work evaluated here.

Two bugs were found and corrected during the review. In one edge case an ATR-based leg with a cold (not yet initialized) ATR indicator could enter a trade with no exit management at all — now it falls back safely to the Python exit path. A second issue caused native bracket exits to log a less informative exit reason tag than the Python path, which would have broken the tearsheet's exit-reason columns; that tag format is now aligned.

Technical / Engineering

Implementation detail and impact, for engineers.

All 12 files in this push are new additions. The actual implementation changes — `_classify_exit_mode`, `_submit_bracket`, `_compute_sl_tp`, the `on_order_filled` branching, and `on_position_closed` flat-reset in `core/managed_strategy.py` — are referenced throughout the artifacts at specific line numbers (e.g. `:165`, `:1125`, `:1877`, `:2021`) but are absent from the diff stat. They exist as pre-existing uncommitted edits evaluated by this commit's artifacts.

The classification logic (`_classify_exit_mode`) routes a leg to `"native_bracket"` only when: `_USE_NATIVE_BRACKET=1` is set, both a fixed SL and fixed TP are present (percentage/points/ATR), the SL and TP actions are both `"close"`, and no trailing / target-lock / sl_wait / tgt_wait / RBO / Move-SL features are active. All other legs fall through to `"python"`. This is evaluated once per leg at config-build time via `config_from_exit`.

For native legs, `_submit_bracket` calls `order_factory.bracket(entry_order_type=MARKET, sl_trigger_price=…, tp_price=…, tp_post_only=False, sl_tags=[…], tp_tags=[…])` and submits the resulting `OrderList` via `submit_order_list`. The three orders carry `ContingencyType.OTO` (entry triggers SL+TP children) with SL↔TP as `OUO` (one fill cancels the other), both `reduce_only`. `on_order_filled` branches on `event.order_type`: `MARKET` → entry fill; `STOP_MARKET` or `LIMIT` → child exit (handled by `on_position_closed` which resets the leg state). `_on_primary_bar` skips `_check_exits` for native legs; `_force_squareoff` calls `cancel_all_orders` before `close_all_positions` to clear resting children race-free. The venue must be configured with `bar_adaptive_high_low_ordering=True` for correct intra-bar SL-vs-TP ordering.

The simulation suite decomposes the flow into three isolated scripts (`sim_phase1_signal.py` → custom `BarAggregator` OHLC correctness on 5-min windows; `sim_phase2_bracket.py` → bracket order contingency and fill mechanics; `sim_phase3_python_exit.py` → Python exit path parity). `sim_sltp_accuracy.py` runs the real `BacktestEngine` for a fixed scenario matrix comparing market-close fills versus bracket fills across three cases. `sim_native_bracket_e2e.py` exercises the full production path (config classification + real engine run) and exits non-zero on any failure. `tests/test_native_bracket.py` and `tests/test_multi_tf_exits.py` integrate into the existing `pytest` suite; all 259 existing tests pass with the flag both off and on.

The code reviews also make a factual correction: L-1 (the unmanaged-position fallback) was initially described as unreachable, but `_classify_exit_mode` admits ATR legs (`sl_atr_multiplier > 0`) before the ATR indicator is warm, so `_compute_sl_tp` genuinely returns 0.0 on the first signal, making the fallback reachable. The fix — `self._exit_mode = "python"` plus `log.warning` before submitting the plain market entry — is confirmed present and re-seeds exit state via the `on_order_filled` Python branch.

Worked Example

A concrete illustration of the most significant change.

The most significant change is the intra-bar SL/TP fill accuracy improvement. Case D from the slippage report — a bar that spans both the stop (1.09900) and the target (1.10200) within a single minute:

Bar OHLC: O 1.10000 / H 1.10260 / L 1.09850 / C 1.10100

Market-order path: checks after bar closes → fills TP exit at bar close → 1.10100 (slip = -10.0 pips from the 1.10200 target) Native-bracket path: O→H→L→C sweep fires SL resting order first (low 1.09850 < SL 1.09900) → fills at trigger price 1.09900 (slip = 0.0 pips)

The bracket correctly identifies that the stop was hit before the target on the bar's downswing and fills at the exact trigger price. The Python market path would have incorrectly exited at the take-profit side and filled 10 pips away from the intended level.
