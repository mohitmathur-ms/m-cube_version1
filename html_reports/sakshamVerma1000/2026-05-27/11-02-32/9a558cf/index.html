Plain English

What this change does, for a non-technical reader.

The single largest file in the project — nearly 6,000 lines of backtest orchestration code — has been split into 17 focused sub-modules, each responsible for exactly one concern (for example: filtering bars by day of week, computing equity curves, applying portfolio stop-loss halts, or merging results across strategy slots). The new layout makes the codebase dramatically easier to navigate, because a developer looking for the portfolio halt logic no longer has to search a 6,000-line file.

Critically, nothing that already calls this code had to change. All existing function names and import paths work identically because the new package re-exports the same public API from a top-level entry point.

The developer-facing README was also substantially expanded. It now documents the full structure of every core sub-package, explains how NautilusTrader's internal components fit together (matching engine, data bus, order types, account/portfolio objects), and includes a visual data-flow diagram showing the path from CSV files through to tearsheet results.

An exploratory mode was added to the exit-management engine (controlled by an environment variable) that lets NautilusTrader's own matching engine fire stop-loss and take-profit triggers using native bracket orders, rather than having m-cube close positions with market orders. This is marked as experimental and is not enabled by default.

Two housekeeping items: the MIT LICENSE file was removed from the repository, and a stray scratch text file was deleted.

Technical / Engineering

Implementation detail and impact, for engineers.

The primary change is the decomposition of `core/backtest_runner.py` (5,809 lines, deleted) into `core/backtest_runner/` (a Python package). The package `__init__.py` (354 lines) defines `__all__` and re-exports every public symbol — `run_backtest`, `run_portfolio_backtest`, `run_backtest_node`, `add_one_hour`, `BacktestNode`, etc. — so all existing call sites in `server.py` and elsewhere import unchanged.

The 5,809 original lines are redistributed (and expanded to ~7,700 total new lines, indicating new logic was also added during the split) across 17 sub-modules, each in its own `__init__.py`: `orchestration/` (519L, top-level portfolio fan-out), `slot_execution/` (1,614L, per-slot and `_USE_GROUPING` shared-engine paths), `portfolio_clip/` (796L, portfolio/user-level SL-TP halt), `portfolio_results/` (930L, multi-slot result merging and splicing), `results/` (392L, per-strategy result extraction), `exit_fill/` (461L, VWAP exit pricing adjustments), `path_b/` (277L, `_USE_BACKTEST_NODE` BacktestNode path), `single_backtest/` (314L, single-strategy run), `portfolio_exit_config/` (375L, DST-aware SL/TP config resolution), `bar_filters/` (173L, weekday and time-of-day bar filtering), `rbo/` (150L, Range Breakout settings), `equity_curves/` (126L, account-based equity curve building), `cross_portfolio/` (91L, in-process event bus for cross-portfolio coordination), `other_settings/` (83L, Other Settings tab), `bar_types/` (73L, `_pair_bid_ask_bar_type` and aggregate-target helpers), `profiling/` (54L, zero-cost `_phase()` context manager), `report_utils/` (31L), and `data_cache/` (29L, `_cached_catalog_bars` TTL cache). A `README.md` (156L) is added inside the package.

`core/managed_strategy.py` received a 520-line diff. Based on the README additions, this introduces the `_USE_NATIVE_BRACKET=1` mode: when active, `ManagedExitStrategy` submits a NautilusTrader bracket order (`order_factory.bracket(...)`) at entry time rather than managing SL/TP exit legs with separate market close orders. The full diff is truncated so the exact implementation is not fully visible.

`README_APP.md` gains a complete sub-module table for each of the four core packages (`backtest_runner/`, `csv_loader/`, `instrument_factory/`, `models/`), a 13-entry NautilusTrader component reference (ParquetDataCatalog through TimeBarAggregator), a Mermaid data-flow diagram covering CSV → catalog → engine → strategy → tearsheet, and a no-lookahead ordering guarantee section.

`.github/scripts/depgraph.py` and `generate_report.py` updated their module-name comment and `DOMAIN_CONTEXT` string respectively to reference `core/backtest_runner/` (the package) instead of `core/backtest_runner.py`. `verify_session_changes.py` received 8-line updates (likely import-path and symbol checks updated for the new package). `.claude/settings.json` adds 14 new allowed `Bash`/`PowerShell`/`Read` patterns used during the split development session.

Worked Example

A concrete illustration of the most significant change.

Before this push, importing the portfolio runner resolved to a function inside the 5,809-line flat file:

# server.py from core.backtest_runner import run_portfolio_backtest # → line ~1200 of backtest_runner.py

After the push, the same import resolves transparently through the package:

from core.backtest_runner import run_portfolio_backtest # → core/backtest_runner/__init__.py re-exports from # → core/backtest_runner/orchestration/__init__.py (the actual implementation)

server.py is unchanged. The `_phase()` profiling helper, previously defined inline in backtest_runner.py, now lives in core/backtest_runner/profiling/__init__.py and is re-exported via the package __init__. A caller doing `from core.backtest_runner import _phase` (or `hasattr(b, '_phase')`) still works, and the zero-cost `None`-bag path is preserved.

Risks & Follow-ups

  • Diff truncated: core/managed_strategy.py changes and most sub-module bodies are not visible — the native bracket order implementation cannot be fully verified from this diff alone.
  • LICENSE deletion removes the project's MIT license. If this is an open-source or shared repo, the absence of a license file means no explicit usage rights are granted. Confirm whether this is intentional.
  • New package is ~1,900 lines larger than the deleted file (7,698 inserted vs. 5,809 deleted). The delta likely represents new logic (Tags, cross-portfolio event bus, AggregatingStrategyMixin wiring) added during the split — this new code was not independently reviewed before being folded in.
  • slot_execution/__init__.py at 1,614 lines is still very large; it may benefit from a further split if it inherits complexity from the original monolith.
  • Back-compat re-exports via __all__ need runtime verification: any internal symbol accessed by string (e.g. getattr(module, name)) that is not explicitly listed in __all__ will silently resolve to None or raise AttributeError after the split.
  • .claude/settings.json now allows Read(//tmp/**) and Bash(git worktree *) — review whether these broad permissions are appropriate for the shared CI/CD settings file.
  • Branch name (feature/order-type-validation) does not match the primary change (file restructure). The native bracket order work in managed_strategy.py — the change that presumably motivated the branch name — is not visible in the truncated diff and needs its own review.
  • Smoke tests (smoke_test_logics_audit.py, stress_test_portfolios.py) and verify_grouping_parity.py should be run against the new package structure to confirm Path A / Path B / grouping parity is preserved.
