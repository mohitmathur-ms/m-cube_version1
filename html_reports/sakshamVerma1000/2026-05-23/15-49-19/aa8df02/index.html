Plain English

What this change does, for a non-technical reader.

The biggest change in this push is a reorganization of the codebase's internal structure. A single large configuration file that defined how portfolios, strategies, and exit rules are stored was broken into ten smaller, focused files — each responsible for one specific job. From the outside the software works identically; the reorganization is purely internal housekeeping to make the code easier to navigate and maintain over time.

A new automated testing pipeline was added to GitHub. Every time code is pushed to the repository, the cloud will now automatically check the code for common errors (using a tool called flake8) and run the project's test suite. This means problems are caught quickly rather than being discovered manually later.

The list of users configured in the system was overhauled. A handful of real-looking test accounts (Alice, Bob, a junior trader, a senior trader, and several edge-case accounts) replaced the previous placeholder user. These accounts are used to verify that the system's permission and trade-sizing rules work correctly under different conditions — including an extreme stress case with a runaway multiplier of 100,000.

The automated reporting system was also updated: report folders are now named using Indian Standard Time (IST) rather than raw UTC, making it easier for the team to correlate reports with when code was actually pushed from their time zone.

Technical / Engineering

Implementation detail and impact, for engineers.

**`core/models.py` → `core/models/` package (the central change):** The 800-line monolith was deleted and replaced with a proper Python package. Ten subdirectories each own one logical concern (`exit_config`, `strategy_slot_config`, `portfolio_config`, `squareoff`, `leg_actions`, `timeframe_utils`, `composite_bar_type`, `serialization`, `persistence`, `slot_sizing`), with logic living directly in each subdirectory's `__init__.py`. The package root `core/models/__init__.py` re-exports every public symbol (and the private helpers `_UNIT_SECONDS`, `_timeframe_seconds`, `_bar_type_timeframe`, `_filter_known_fields`, `_migrate_legacy_trade_size`) so `from core.models import …` is fully backward-compatible for all consumers: `server.py`, `core/backtest_runner.py`, `core/managed_strategy.py`, `core/templates.py`, and the test suite. The dependency graph inside the package is acyclic; `serialization/_migrate_legacy_trade_size` and `slot_sizing/effective_slot_qty` continue to import `core.venue_config` / `core.users` lazily inside function bodies to avoid circular imports at collection time.

**`strategies/_shared/` package:** A new shared-utilities namespace was introduced for strategies. The visible subdirectories are `entry_tags/`, `leg_state/`, and `time_windows/` (which exposes `hhmm_to_min`). The diff is truncated past this point, but all five strategy files (`bollinger_bands.py`, `ema_cross.py`, `four_ma.py`, `range_breakout.py`, `rsi_mean_reversion.py`) show diffs, indicating they were updated to import from `_shared` rather than duplicating utilities inline.

**`.github/workflows/python-app.yml` (new):** A standard `ubuntu-latest` CI job that runs on every push except paths under `html_reports/**` (to avoid CI loops from the push-report bot commits). Steps: checkout → `setup-python@v5` with `cache: pip` keyed on `requirements.txt` → `pip install flake8 pytest` + `requirements.txt` → `flake8` (hard-fail on `E9,F63,F7,F82`; advisory on everything else) → `pytest tests/`.

**`push-report.yml` updated:** The `report_dir` output is now `html_reports/${GITHUB_ACTOR}/${IST_DATE}/${IST_TIME}/${SHORT_SHA}` where `IST_DATE` and `IST_TIME` are derived by running `date` with `TZ='Asia/Kolkata'` (colons replaced with dashes since `:` is illegal in path components). Previously the path was flat: `html_reports/${ACTOR}/${SHA7}`.

**`config/users.json`:** `_default` multiplier changed from `6` to `1.0`. The single placeholder user `u_mownziwo` was replaced with eight named test fixtures exercising the full permission-and-sizing matrix: `alice` (FX instruments, ×2), `bob` (crypto-only, ×0.5), `trader_safe` (junior, ×0.01), `trader_agg` (senior, ×3, unrestricted), `runaway` (×100000 stress case), `alice_only` (EURUSD only, ×1.5), `noaccess` (empty allowlist), `case_test` (lowercase allowlist — case-sensitivity probe).

**`core/backtest_runner.py`:** Single-character change: trailing newline removed from the last line of `_apply_vwap_fill`. No behavioral change.

**`portfolios/_default/FX_9_Slot_2024.json`:** Portfolio JSON updated; the diff shows ~106 lines changed — likely a round-trip through the `_migrate_legacy_trade_size` migration path that converts old `trade_size` fields to the new `lots` representation.

**`.claude/settings.json`:** 27 additional Bash/PowerShell commands added to the allowed list, all of them import-verification, pytest invocation, or verify-session-changes patterns used during the modularization session.

Risks & Follow-ups

  • The README.md inside core/models/ states 'The original core/models.py is kept in the repo as a shadowed backup' — but the diff shows it was deleted. This documentation claim is incorrect and could mislead future contributors.
  • The diff is truncated; the full content of all five updated strategy files and several new __init__.py modules is not visible, so correctness of those imports cannot be fully verified from this diff alone.
  • config/users.json now contains a 'runaway' user with multiplier=100000.0 and a 'noaccess' user with an empty allowlist. If production deployments share this file these accounts will be live — they appear to be test fixtures that should ideally live only in a test-fixtures file.
  • The new python-app.yml CI runs pytest tests/ against ubuntu-latest; the project is Windows-first (start.bat, venv\Scripts\python.exe paths). Any test that relies on Windows path separators or PowerShell will fail in CI — verify the test suite is OS-portable.
  • trailing newline removed from core/backtest_runner.py — POSIX convention requires a final newline; flake8 W292 will now warn on this file in CI.
  • push-report.yml now writes reports under a deeper nested path (actor/date/time/sha) — any downstream tooling or links that assumed the old flat actor/sha path will break.
  • No mention of running verify_session_changes.py in CI — the CLAUDE.md designates this as the authoritative wiring checker, but the new workflow only runs pytest.
