Plain English

What this change does, for a non-technical reader.

Every time code is pushed to this repository, an automated HTML report is generated summarising what changed. This push makes those reports significantly richer and easier to read.

Three improvements stand out. First, the report now includes a "Worked Example" section: the AI is asked to produce one concrete illustration of the most important change — a before/after snippet, a sample input and output, or a representative call path — making the technical content tangible for readers who want to understand impact quickly.

Second, the report now contains a visual "Dependency / Knowledge Graph" section. A new tool scans the Python source files in the repository (without contacting any external service) and draws a diagram showing which other files depend on the files that were just changed, and which files those changed files themselves import. This helps reviewers see the blast radius of a change at a glance.

Third, the overall report layout was upgraded to match a polished "guide" style: a gradient cover header, a clickable table of contents, colour-coded callout boxes for each section, and anchor links so readers can jump directly to the section they care about.

On the housekeeping side, a file that provided instrument-creation logic (core/instrument_factory.py) was deleted — its contents have apparently been absorbed elsewhere — and the CI pipeline was upgraded to run on Python 3.12 instead of 3.11.

Technical / Engineering

Implementation detail and impact, for engineers.

The report generation pipeline (`.github/scripts/generate_report.py`) received the largest set of changes. Two new modules are now imported: `depgraph` and `depgraph_svg`.

`depgraph.py` (new, 221 lines) is a pure-stdlib AST-based import scanner. `build_module_index(repo_root)` walks the repository with `os.walk`, skipping directories in `_SKIP_DIRS` (venv, .git, .github, catalog, etc.), and maps every first-party dotted module name to its repo-relative POSIX path. `build_edges` then parses each `.py` file's AST to collect `ast.Import` and `ast.ImportFrom` nodes, resolves them against the module index (with a longest-prefix walk to handle `from pkg.mod import Symbol`), and emits `(importer_path, imported_path)` directed edges. Relative imports are resolved by `_abs_module_for_relative` using the importing file's package-path prefix. `neighbors_for(changed_files, edges)` slices the full edge set down to the changed files and their 1-hop neighbours, returning a structured dict with `changed`, `non_py`, `per_file`, `nodes`, and `edges` keys. `graph_for_push` is the one-shot convenience wrapper used by the report.

`depgraph_svg.py` (new, 183 lines) consumes that dict and renders a pure-SVG three-column diagram (no JavaScript, no CDN) — left column: files that import the changed files; middle: the changed files (highlighted orange); right: files imported by the changed files. Arrows use an SVG `<marker>` arrowhead. `render_tables` produces a dark HTML adjacency table (`<table class='dep'>`) listing each changed `.py` file's inbound and outbound edges. Both functions are tolerant of empty graphs.

In `generate_report.py`, the AI tool schema (`REPORT_TOOL`) gained an `"example"` field (type: string) and `"example"` was added to `required`. A new constant `CORE_FIELDS = ("headline", "plain_english", "technical")` separates hard-required fields from soft-required ones (`example`, `changed_files`, `risks_or_followups`), so a model that omits `example` does not trigger degraded mode. `_build_graph(meta)` calls `depgraph.graph_for_push` inside a broad `except` so a graph failure never breaks the report. `render_html` was extended with `graph: dict | None = None` and now emits two new `<section>` elements (`sec-example`, `sec-graph`) and a `<nav class='toc'>` table of contents.

`_style.py` gained ~73 lines of CSS covering the guide component kit: `.cover` gradient header, `nav.toc` two-column TOC, `.simple` / `.callout` / `.callout-tech` / `.callout-ok` / `.callout-warn` left-bordered callouts, `.badge-*` chips, `.filebox` filename labels, `table.dep` / `table.example` dark adjacency tables, and `.depgraph` SVG container.

`core/instrument_factory.py` was deleted entirely (183 lines). This module provided `create_instrument()` for building NautilusTrader `CurrencyPair` objects with precision tables for FX and crypto. Any callers must now use whatever replaced it (not visible in this diff).

The CI workflow bumped `python-version` from `"3.11"` to `"3.12"` in the `actions/setup-python@v5` step.

Worked Example

A concrete illustration of the most significant change.

Before this push, `generate_report.py` asked the AI for two fields — `plain_english` and `technical` — and the report had no dependency section.

After this push, the script calls `depgraph.graph_for_push(".", meta["changed_files"])` before rendering. For the current push (which modified `generate_report.py`, `depgraph.py`, `depgraph_svg.py`, `_style.py`), the call returns something like:

```python { "changed": [".github/scripts/depgraph.py", ".github/scripts/depgraph_svg.py", ".github/scripts/generate_report.py"], "non_py": [".claude/settings.json", ".github/workflows/python-app.yml"], "per_file": { ".github/scripts/generate_report.py": { "depends_on": [".github/scripts/depgraph.py", ".github/scripts/depgraph_svg.py", ".github/scripts/_style.py"], "depended_on_by": [] }, ... }, "nodes": [...], "edges": [["generate_report.py", "depgraph.py"], ...] } ```

`depgraph_svg.render_svg(graph)` converts that into an inline `<svg>` three-column diagram embedded directly in the HTML report — no network call required.

Risks & Follow-ups

  • core/instrument_factory.py was deleted with no visible replacement in this diff — any callers (csv_loader, nautilus_loader, backtest_runner) must be confirmed to import the equivalent from wherever the logic moved, or runtime errors will occur on instrument creation.
  • The depgraph scanner skips the .github directory itself (it's in _SKIP_DIRS), so the newly added depgraph.py / depgraph_svg.py / generate_report.py imports are not self-indexed — the graph section in the report for this very push may show those files as having no Python neighbours.
  • Python 3.12 CI bump: verify that all dependencies (nautilus_trader==1.224.0, pyarrow==23.0.1, etc.) have 3.12 wheels available; 3.12 removed several deprecated stdlib APIs that older Nautilus versions may rely on.
  • CORE_FIELDS relaxation means a model response missing 'example' silently produces a report with a placeholder — consider logging a warning when optional fields are absent so degraded output is observable.
  • The SVG layout is fixed-width (940 px, max 12 nodes per column); large pushes touching many files will silently truncate the graph with '(+N more)' — could be misleading for wide-impact refactors.
