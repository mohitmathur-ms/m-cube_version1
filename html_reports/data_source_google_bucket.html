Google Cloud Storage Bucket

What it takes to load CSV market data from a GCS bucket instead of a local folder path.

1. How it fits the current flow

Today the app loads data by scanning a local folder: scan_csv_folder(folder) calls Path(folder) and walks the directory layout. A GCS bucket is not a local path, so the cleanest approach is sync-then-scan: pull the bucket's CSVs down to a local staging folder, then hand that folder to the existing scanner unchanged.

GCS bucket→ download to staging folder→ scan_csv_folder()→ catalog

No layout scanner changes are needed — the folder structure (FX daily, crypto nested, commodity, etc.) is preserved during the download.

2. Requirements

ItemDetail
GCP projectA Google Cloud project that owns the bucket.
BucketName + region; the CSVs in the same folder layout we use locally.
CredentialsService-account JSON key with roles/storage.objectViewer (read-only) on the bucket.
Python librarygoogle-cloud-storage (add to requirements.txt).
NetworkOutbound HTTPS (443) to storage.googleapis.com.
Local diskFree space to stage the downloaded CSVs (FX catalogs are large).
Store the service-account key outside the repo and reference it via an env var (e.g. GCS_KEY_FILE), never commit it.

3. Process (step by step)

  1. Authenticate — point the client at the service-account key: 
    set GOOGLE_APPLICATION_CREDENTIALS=C:\keys\mcube-gcs.json
  2. List objects under the chosen prefix (the "folder" the user picks): 
    from google.cloud import storage
client = storage.Client()
bucket = client.bucket("mcube-market-data")
blobs  = bucket.list_blobs(prefix="fx/EURUSD/")
  3. Download each blob to a local staging dir, preserving the relative path: 
    dest = staging / blob.name
dest.parent.mkdir(parents=True, exist_ok=True)
blob.download_to_filename(dest)
  4. Scan the staging dir with the existing pipeline: 
    entries = scan_csv_folder(str(staging))
  5. Load as normal — load_csv_and_store writes into the catalog.

4. Where it touches our code

  • UI: add a "Source: Google Bucket" choice on the Load Data page; collect bucket name + prefix instead of a filesystem path.
  • Server: a small resolver in front of /api/csv/scan that, when source = GCS, runs the download into a per-user staging folder and then passes that local path into scan_csv_folder.
  • Scanners: no change — they keep reading local files.

5. Gotchas

  • Re-download only changed files (compare blob.updated / size / md5) so refreshes stay fast.
  • Large buckets: stage incrementally by prefix, not the whole bucket at once.
  • Egress from GCS is billed — co-locate or cache to avoid repeated full pulls.
