L4 · utility core/_pandas_utils.py

Column-major row iterator that replaces DataFrame.iterrows() in hot paths.

Purpose

Provide a fast row iterator for the few places that genuinely need to walk a DataFrame row-by-row (report building, per-trade post-processing). ~5× faster than iterrows by materializing each column with .tolist() once and then zipping the lists.

Key Logic
  • iter_columns(df, *names) — for each requested name, either yields the column's .tolist() or falls back to a list of None when the column is missing, then zips them and yields one tuple per row.
  • Missing-column fallback matches the optional-column pattern downstream so callers don't need to pre-check col in df.columns.

L0 · ingest core/csv_loader.py

Scan folders of OHLCV CSVs across crypto / FX / commodity / index layouts and load them into clean DataFrames.

Purpose

First stage of the ingest pipeline. Detects which on-disk layout the user has (flat {id}_{SYMBOL}_{Name}.csv, consolidated per-pair files, FX daily-file tree, commodity daily-file tree, or single-stream index files), exposes them as selectable entries to the UI, then loads the bytes into pandas with PyArrow-backed parsers tuned for the FX timestamp format. Synthesises MID bars from ASK + BID at load time.

Key Logic
  • scan_csv_folder(folder) — fall-through detection: consolidated FX → flat crypto → FX daily → commodity daily → index daily. Returns a list of dicts {path, filename, id, symbol, name, …}.
  • _scan_fx_daily_layout / _scan_commodity_daily_layout aggregate thousands of YYYY/MM/DD/*.csv files into three entries per symbol — ASK, BID, MID — so the UI exposes each side as its own selectable instrument. Each entry carries the full ask_files / bid_files lists; MID is synthesised at load.
  • _scan_index_daily_layout emits a single entry per root (no ASK/BID split, single stream), with a synthetic display filename shaped like the consolidated FX naming so the UI's asset-class filter still matches.
  • Module-level mtime-keyed caches (_FX_SCAN_CACHE, _COMMODITY_SCAN_CACHE, _INDEX_SCAN_CACHE) skip re-walking the tree on every UI refresh. Stale entries fall back to a TTL safety-net of 600s.
  • load_csv() — PyArrow CSV reader (~35× faster than pandas on 4M-row files). FX timestamps (DD.MM.YYYY HH:MM:SS GMT±HHMM) are reshaped to ISO-8601 in vectorised pyarrow.compute string ops then cast to timestamp[ns,UTC] — measured ~22× faster than pd.to_datetime(format=…).
  • concat_side(files) — parallel daily-file load via ThreadPoolExecutor (default 16 workers). pandas releases the GIL inside the C parser so I/O overlaps cleanly.
  • _merge_ask_bid_to_mid(ask, bid) — inner-join on timestamp, OHLC = average, volume = sum, capped at QUANTITY_MAX; per-side extras (e.g. ask_vwap / bid_vwap) are carried through unchanged.

L0 · ingest core/nautilus_loader.py

Bridge from raw CSV DataFrame to a populated NautilusTrader ParquetDataCatalog.

Purpose

Second stage of ingest. Takes the entry dicts produced by scan_csv_folder, loads the underlying CSV(s), builds a Nautilus instrument via create_instrument, wrangles the OHLCV rows into Bar objects, and writes both the instrument and the bars to a ParquetDataCatalog on disk. Also owns the cache of opened catalog handles.

Key Logic
  • load_csv_and_store(csv_entry, catalog_path, venue, data_format) — main entry point. Dispatches on entry shape: files list (single-stream index) → concat_side; ask_files + bid_files + side=MID → load_pair_mid; ask_files/bid_files + side=ASK|BID → concat_side on the chosen side; otherwise → single-file load_csv.
  • wrangle_bars() — wraps Nautilus's BarDataWrangler to turn the OHLCV DataFrame into a list of Bar objects.
  • save_to_catalog() — writes instrument + bars to catalog/; skips the instrument write when already present so re-ingest is cheap.
  • load_catalog(path) — per-path ParquetDataCatalog cache (_CATALOG_CACHE guarded by _CATALOG_LOCK) so the 50–300ms manifest read isn't paid on every API call.
  • Doji sanity check — samples up to 1000 wrangled bars and logs a warning if >30% have open == close (a clear sign of insufficient price precision).

L0 · ingest core/aggregator.py

Pure-pandas OHLCV resampling + derived-feature computation; mirrors Nautilus's TimeBarAggregator semantics.

Purpose

Convert a 1-minute OHLCV DataFrame into a coarser-timeframe DataFrame and optionally append 14 derived features (EMAs, RSI, ATR, VWAP, true range, log/pct returns, body / wick geometry). Driven offline by scripts/aggregate_catalog.py — not invoked inside the live backtest engine.

Key Logic
  • aggregate_ohlcv(df, timeframe, …) — pandas resample(rule, closed='right', label='right') so the window (T-N, T] is stamped at T, matching Nautilus's TimeBarAggregator convention exactly.

  • aggregate_with_features() — convenience wrapper: resample + feature compute in one call.

L0 · ingest core/fx_rates.py

Timestamp-aware FX rate resolver that converts cross-currency PnL to the venue's account base currency.

Purpose

A USDJPY trade settles in JPY; without conversion the JPY PnL would be silently dropped from the USD account. This module loads the venue's fx_conversion rules from its adapter config and converts every per-trade amount at the FX rate nearest and not after the trade timestamp. Supports both static rates and catalog-sourced pairs (daily-MID preferred, with graceful fallback to LAST or a configured constant).

Key Logic
  • Dataclasses: _RuleStatic (fixed scalar) and _RuleCatalog (catalog pair + is_inverse flag + fallback rate).
  • FxRateResolver:
    • from_adapter_config(adapter_cfg, catalog_path) — factory that parses the venue's account_base_currency and fx_conversion rules.
    • convert(amount, from_ccy, at_timestamp) — same-currency pass-through; missing rule → identity; catalog miss → configured fallback or identity.
    • _get_series(pair) — lazy load FX series from ParquetDataCatalog, preferring 1-DAY-MID → 1-DAY-LAST → MID → LAST; cached on the instance.
    • _lookup_price(series, at) — asof lookup on a sorted UTC-indexed series; forward-fills weekends and falls back to the latest if the timestamp precedes the series start.
  • _decode_nautilus_price_column(col) — zero-copy decode of Nautilus fixed-precision int64 prices (1e9 scale) from PyArrow arrays, FixedSizeBinary(8) blobs, or pandas Series. Handles float64, int64 / uint64, and binary formats interchangeably.
  • parse_money_string(s) — split Nautilus Money strings (e.g. "-1234.56 JPY") into (amount, ccy).

L1 · signal core/signals.py

Registry of pure entry-signal functions and their indicator dependencies.

Purpose

For a strategy to be wrapped by ManagedExitStrategy it needs a stateless signal function. This module is the registry of those functions plus a declarative description of the Nautilus indicators each one needs. The exit engine looks up the entry by name and feeds it pre-computed indicator values + position-state booleans on every bar.

Key Logic
  • ema_cross_signal(fast, slow, …) — BUY when fast ≥ slow, SELL when fast < slow (crosses only — keeps the state machine in ManagedExitStrategy).
  • rsi_signal(rsi, overbought, oversold, …) — BUY at / below oversold, SELL at / above overbought.
  • bollinger_signal(close, lower, upper, …) — BUY at the lower band, SELL at the upper band.
  • four_ma_signal(v1..v4, …) — BUY when v1 > v2 > v3 > v4 (alignment), SELL on the inverse.
  • SIGNAL_REGISTRY[name] = {signal_fn, indicators, extract_args} — extract_args is a small lambda that assembles the named arguments for signal_fn from the indicators dict + slot params dict so the runner stays decoupled from each signal's signature.

L1 · strategy core/custom_strategy_loader.py

Discover, validate and merge user-uploaded strategy .py files with the built-in registry.

Purpose

Lets users drop a .py file under custom_strategies/<user_id>/ and have it show up alongside the built-in strategies in the UI. Performs a strict 6-phase validation before exposing anything so a broken upload never poisons the registry.

Key Logic
  • validate_and_load_strategy(file_path) — six phases: (1) file checks (exists, non-empty); (2) module load via importlib.util (catches and reformats syntax errors); (3) required exports present (STRATEGY_NAME / STRATEGY_CLASS / CONFIG_CLASS / DESCRIPTION / PARAMS); (4) type checks (str / class inheritance / dict); (5) config & strategy method validation (instrument_id / bar_type / trade_size on the config; on_start / on_bar / on_stop on the strategy); (6) PARAMS dict cross-referenced against the config fields (numeric params must have min/max and a default in range).
  • load_all_custom_strategies(dir) — glob *.py, skip dunder files, validate each, de-duplicate by strategy name, returning (strategies_dict, warnings).
  • get_merged_registry(custom_dir) — thread-safe (lock + double-check on a per-dir mtime signature) merge of built-ins plus customs; collisions get a "(Custom) " prefix to keep the built-ins as the canonical name.
  • get_strategy_template() — returns a well-commented template .py file for the UI's "new strategy" flow.
  • get_strategy_guidelines() — markdown docs of the contract (required exports, indicators list, common patterns).

L3 · schema core/models.py

Portfolio / slot / exit dataclasses, JSON persistence, legacy-field migration, leg-action validation.

Purpose

The schema of everything the user can configure. Three nested dataclasses describe a portfolio; helper functions load and save them as JSON under portfolios/<user_id>/; one helper migrates the legacy trade_size field into the new lots × lot-size model so old saved portfolios keep loading.

Key Logic
  • ExitConfig — every per-leg exit knob: SL type (none / percentage / points / trailing / ATR), SL value, trailing offsets, SL/Target wait (sec or bars), target lock (snap SL to a floor once profit ≥ trigger), per-leg trailing target, action combos (close / re_execute / reverse / execute / re_entry / keep_leg_running; up to 3 comma-separated), cross-leg fields, squareoff override.
  • StrategySlotConfig — slot identity (8-char UUID), strategy name + params, bar type, lots, allocation %, enabled flag, start/end date, slot-level squareoff override, embedded ExitConfig.
  • PortfolioConfig — capital, max loss/profit, allocation mode (equal / percentage), date filters, weekday filter (run_on_days), entry-window filter (entry_start_time / entry_end_time), portfolio-level squareoff, RBO knobs, "Other Settings" knobs, portfolio SL / trailing SL, Move SL to Cost (portfolio-aggregate flavour), portfolio target / trailing target, ReExecute-tab suppressors, monitoring flags (live-only), slots: list[StrategySlotConfig].
  • resolve_squareoff(portfolio, slot) — 3-level priority chain: leg > slot > portfolio.
  • parse_leg_actions(s) / validate_leg_actions(s, has_execute_target) — split CSV, deduplicate, enforce spec rules (at most 3, keep_leg_running solo, re_execute and re_entry exclusive, execute requires a target leg).
  • portfolio_from_dict() rebuilds a config from dict; calls _migrate_legacy_trade_size on each slot — that translates the old trade_size field into lots = trade_size / lot_size by looking up the venue config.
  • effective_slot_qty(slot, user_id) → min(lot_size × lots × user_multiplier, trade_size_cap).
  • Persistence: save_portfolio, load_portfolio, list_portfolios, delete_portfolio — all under portfolios/<user_id>/<name>.json.

L2 · exit engine core/managed_strategy.py

The SL/TP/trailing/target-lock/RBO state machine that wraps any entry signal.

Purpose

Heart of the portfolio system. Wraps a stateless signal from SIGNAL_REGISTRY with a complete exit-management lifecycle: intra-bar SL / TP, sec/bar waits, Move SL to Cost, trailing SL, target locks, per-leg trailing target, multi-action exit dispatch (close / re_execute / reverse / execute / re_entry / keep_leg_running), intra-day entry windows, range-breakout (RBO) entry gating, squareoff, and cross-slot Hit-On-Leg signalling via a shared in-memory event bus.

Key Logic
  • on_bar state machine (resolved each tick):
    1. Format routing: Format A buffers a BID/ASK/PRIMARY trio in _fa_pending until all three arrive; B/C dispatch directly.
    2. RBO phase: IDLE → MONITORING → ENTRY → DONE; daily reset.
    3. Squareoff check: compare local-time vs squareoff_time in squareoff_tz; force-close and block re-entry until next session.
    4. Exit checks (when in position): Move SL to Cost variants (incl. "for All Legs Despite Loss/Profit", LTP+buffer slide, Hit-On-Leg cross-slot trigger, portfolio-aggregate trigger), trailing SL (basic ratchet or post-move dedicated trail), target lock, per-leg trailing target via advance_trailing_target, SL hit (long: low ≤ SL; short: high ≥ SL) with sec/bar wait gating, TP hit (mirror) with target-wait gating.
    5. Entry checks (when flat): Execute-arm consumption from the sibling bus, ReEntry price gate (must cross back through entry level), Re-execution delay (delay_between_legs_sec), Intra-day entry-window block, RBO ENTRY-phase gating, signal lookup & side resolution, _submit_order + _set_exit_levels.
  • _handle_exit(kind, is_long, close) — publish hit timestamp to the cross-slot bus, parse up to 3 actions, apply on_sl_action_on / on_target_action_on filters (suppress on trailed vs fixed), respect ReExecute suppressors (no_reexec_sl_cost, no_reentry_sl_cost), close with a structured reason tag (_expecting_close_fill=True so on_order_filled doesn't misclassify the close as a new entry), then dispatch each action.
  • on_order_filled() — on entry, compute SL/TP from type+value (percentage / points / ATR / none); snap to the instrument tick; reset per-position counters.
  • RBO state machine (_rbo_step): IDLE → MONITORING (accumulate high/low) → ENTRY (detect breakouts on the configured side(s)) → DONE; rbo_cancel_other_side defers DONE to next bar so this bar's breakout still fires; range buffer + entry end mark the close of the window.
  • advance_trailing_target(active, stop, anchor, …) — pure function ratcheting profit-lock: activation at tgt_trail_when_profit_reach, floor at tgt_trail_lock_min_profit, ratchet by tgt_trail_by every tgt_trail_every percent profit.
  • resolve_trigger_hl(...) — three-format trigger resolver: Format A picks BID for long-SL / ASK for short-SL, Format B uses OHLC, Format C uses close-only.
  • Cross-slot bus: _CROSS_SLOT_EVENT_BUSES[portfolio_id][slot_id] stores sl_ns, tgt_ns, arm_ns timestamps so siblings can react to each other (Hit-On-Leg, Execute arm).

L3 · orchestration core/backtest_runner.py

The portfolio runner. Loads bars, dispatches per-slot or per-group engines (Path A / Path B), merges results, applies portfolio-level clipping.

Purpose

Top-level driver invoked from server.py. Owns the choice between single-strategy mode and multi-slot portfolio mode, the three execution paths (per-slot Path A, grouped Path A, Path B BacktestNode), worker-pool dispatch, day/time filters, FX-rate conversion of cross-currency PnL, two-pass portfolio-aggregate Move SL detection, and the final clip pass that enforces portfolio + user SL / TP / trailing levels on the merged equity curve.

Key Logic
  • run_backtest(catalog_path, bar_type, strategy_name, params, …) — single-strategy entry point; routes to run_backtest_node when Path B is active.
  • run_portfolio_backtest(portfolio, catalog_path, …) — multi-slot entry; for each enabled slot either spawns its own engine (_run_single_slot) or, when _USE_GROUPING=1 and slots share (bar_type, start_date, end_date, custom_strategies_dir), batches them into a shared BacktestEngine via _run_slot_group.
  • _extract_slot_from_group_reports — after a shared engine run, walks engine.trader.strategies() (Nautilus reassigns IDs internally — never trust the pre-run ID), filters positions by strategy_id, synthesises a per-slot equity curve from the shared reports.
  • _run_single_backtest_task — worker entry; calls get_merged_registry via importlib reload so custom strategies are available inside child processes.
  • Portfolio clipping pipeline: _merge_portfolio_results calls _apply_portfolio_clip which walks the merged equity curve and runs _pf_sl_clip (portfolio SL: combined-loss / underlying-movement / loss-and-range), _pf_tgt_clip (portfolio target), _user_sl_clip + _user_tgt_clip (user-level cumulative SL/TP across portfolios). All three respect Delay (sec) and re-execute counters.
  • Day / time filters: weekday list and intraday entry-window applied as bar-list pre-filtering in Path A; _chunk_data_configs_for_path_b emits one BacktestDataConfig per allowed day for Path B. Path B auto-falls-back to Path A when filters are active.
  • Per-worker bar cache: _cached_catalog_bars is an lru_cache(maxsize=4) so repeated runs on the same (bar_type, start, end) reuse the in-memory bar list.
  • FX conversion: FxRateResolver converts each trade's PnL to the venue's account base currency before merging into the portfolio equity curve.
  • RBO wrapper: when rbo_enabled the runner wraps the raw signal with config_from_exit → ManagedExitStrategy.
  • Phase profiling: _phase("label", phase_bag) context manager is zero-cost when phase_bag is None; populated only under _PROFILE_PHASES=1.

L4 · identity core/users.py

Identity-only multi-user layer: validates X-User-Id headers and exposes per-user scalars (multiplier, caps, trailing rules, instrument allowlist).

Purpose

There is no authentication — the server only checks that the X-User-Id header is on file in config/users.json. This module reads / writes that registry and exposes per-user knobs the runner consults at backtest time: trade-size multiplier, absolute loss / profit caps, trailing-SL and trailing-target rules, an optional instrument allowlist, plus an in-memory cumulative-PnL aggregator for the level-3 user-cross-portfolio clip.

Key Logic
  • Startup: _seed_if_missing() guarantees config/users.json exists with at least a _default user.
  • validate_user_id(s) — slug regex ^[a-z0-9_-]{1,32}$.
  • load_users() / save_users() — disk I/O with graceful fallback to a minimal default if the JSON is corrupt or missing.
  • list_users() returns a public-safe slice (user_id + alias only); get_user(uid) returns the full record.
  • Per-user lookups: get_multiplier, get_user_max_loss, get_user_max_profit, get_user_trailing_sl (returns {"every", "by"}), get_user_trailing_target (returns {"when_reach", "lock", "every", "by"}), get_allowed_instruments / is_instrument_allowed.
  • Cumulative PnL: _USER_PNL_AGGREGATOR (in-memory dict) + get_user_cumulative_pnl / add_user_pnl (EMA-smoothed) / reset_user_pnl.
  • Pre-save validation: validate_registry_payload(payload) rejects dupe user IDs, non-positive multipliers, malformed lists.

L4 · migration core/migrate_users.py

Purpose

L4 · scheduler core/runtime_history.py

Persistent EMA of wall-time-per-day for each (bar_type, strategy) pair to inform LPT scheduling.

Purpose

When the scheduler decides which slots to dispatch first (Longest-Processing-Time-first), it would otherwise have to use a span-only heuristic. This module remembers how long previous runs took per (bar_type, strategy) and feeds back a smoothed estimate.

Key Logic
  • load() / save(data) — read / write <root>/.runtime_history.json, thread-safe on the write side.
  • record(data, bar_type, strategy, elapsed, span_days) — per-day rate = elapsed / span_days; EMA blend 0.3 × new + 0.7 × prev; circular sample buffer capped at 20; timestamp recorded.
  • estimate(data, bar_type, strategy, span_days) → per_day × max(1, span_days) or None if no history is recorded yet (caller falls back to span-only).

L4 · report core/report_generator.py

Turn raw Nautilus backtest results into the self-contained HTML tearsheet (docs/report_template.html).

Purpose

Reads the positions / fills DataFrames Nautilus emits at the end of a run, normalises the column names and Money/Quantity strings, derives a per-trade ORDERBOOK + LOGS + SUMMARY data structures, and embeds them as JSON inside the HTML report template. The result is a single shareable .html file with everything inline.

Key Logic
  • _parse_nautilus_value(s) / parse_money_string equivalents — strip the "NUMBER CCY" suffix.
  • _format_timestamp / _format_timestamp_series — vectorised DD-MM-YYYY HH:MM:SS format with per-cell fallback for unparseable rows.
  • _resolve_column(df, candidates) — alias resolver for Nautilus's evolving column names.
  • _determine_reason(order_type, is_reduce, …) — priority order: tags > order_type/contingency > fallback. Returns human-readable strings like "Stop Loss", "Take Profit", "OCO Exit", "Strategy Signal".
  • _build_fills_lookup(fills_report) — builds three lookups: by venue order id (legacy), by (trader_id, strategy_id, instrument_id, ts_seconds), and role-split open/close variants so a reverse-on-SL fill can be told apart from the entry fill on the same bar.
  • _build_orderbook(all_results, user_id) — turns each closed position into a single dict (USERID, SYMBOL, EXCHANGE, …, ENTRY/EXIT TIME, ENTRY/EXIT PRICE, ENTRY/EXIT REASON, PNL); scales LOTS / MULTIPLIER via core.users.get_multiplier when a user_id is given (lazy import).
  • build_logs_dataframe(all_results, …) — emits "ENTRY | reason | side qty symbol @ price | OrderID / PositionID" lines per fill.
  • _build_summary(orderbook) — group trades by DD-MM-YYYY date, compute cumulative PnL per day, capture max/min peaks + the timestamps they occurred at.
  • generate_report(all_results, …) — load the template, substitute {{ORDERBOOK_JSON}}, {{SUMMARY_JSON}}, {{LOGS_JSON}}, {{DATE_RANGE_JSON}}, {{BACKTEST_NAME}}; return the rendered HTML string (caller writes to disk).
