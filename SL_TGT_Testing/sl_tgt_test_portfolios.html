How to use: run the portfolio → export the orderbook → walk the manual trace → confirm the engine matches at each step. Verify relative to the realised fill (entry price isn't controlled).

Combination & odd-type cases (the tricky ones)

Single-feature cases (TL/TP/TU) prove each rule in isolation; these deliberately stack features and hit corners to prove the rules still hold when they collide. They layer on the existing PFs, so they're not in the §2 one-feature matrix.

TC-1 · Same-bar level race (precedence) — PF-U. One bar makes a leg SL, the portfolio Combined Loss, and the user Max Loss all true together. Expected: User→Portfolio→Leg — USER_SQOFF fires and force-flats both books; leg/portfolio hits subsumed under the user reason, not three independent exits. Pass: one USER_MAX_LOSS exit per leg, same bar; no double-count; no re-entry.
TC-2 · Trail-step + breach same bar — PF-3. A bar ratchets the Trailing SL up then trades back through the new stop in the same bar. Expected: tighten current_sl first, then test the hit against the new level → exit same bar. Pass: TRAIL_SL at the ratcheted level, not the old one (guards stale-level).
TC-3 · Move-to-Cost then gap-through — PF-2. Move-SL-to-Cost sets SL = entry; the next bar opens past entry. Expected: fill per the gap rule — at the level or the worse open? Pass: behaviour explicit + matches the agreed rule — the concrete trade that settles the parked gap question (Q2).
TC-4 · Re-Execute into an instant re-stop — PF-1L (SqOff+Re-Execute, count 2). SL hit → re-enter next bar → fresh SL hit on that same re-entry bar. Expected: re-exec counter increments, 2nd exit attributed to the re-executed leg (_2), limit still caps entries. Pass: exactly the allowed entries; no loop; counts right.
TC-5 · Trailing SL vs fixed Combined Loss — PF-3. Both a fixed Combined Loss (5000) and a Trailing SL ratcheted tighter than 5000. Expected: the tighter stop governs; the fixed value is the floor, never loosens the trail. Pass: exit at the tighter level; compose by min-distance, no double-fire.
TC-6 · Cross-PF start racing a self-entry — PF-XPF. PF-A fires "Start Other (PF-B)" with a 2 s delay; within the delay PF-B's own EMA entry also triggers. Expected: PF-B enters once; external Start + self-entry don't stack; delay honoured. Pass: single PF-B entry; one entry reason.
TC-7 · Boundary — exactly at the threshold — PF-3. A bar lands combined PnL at exactly −5000.00 (post tick-snap + FX). Expected: the ≤/< convention is explicit (we use ≤ → fires at the level). Pass: fires at exactly −5000; equality not skipped.

8. How to check manually (the verify loop)

  1. Run the portfolio → export the orderbook (fills, exits, reasons, per-bar current_sl/levels).
  2. For each entry: logged fill → apply the case formula → tick-snap → compare to the engine. Match to the tick.
  3. For each dynamic feature (move-to-cost, trailing, profit-lock, user cascade): walk the manual trace row by row against the engine's per-bar log — level must change on the same bar, by the same amount.
  4. For each exit: confirm trigger condition (bar low/high / pnl vs level) and the fill.
  5. Record green/red; red rows carry the offending trade/bar.
